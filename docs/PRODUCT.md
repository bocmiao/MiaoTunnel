# 产品定义

## 一句话定位

MiaoTunnel 是一个面向 NAS、家庭实验室和小团队的自托管 Web 服务发布器：在自己的 VPS 上部署入口，在内网设备运行 agent，通过中文控制台安全地得到 HTTPS 地址。

它不是新的传输协议，也不是 VPN、CDN、开放代理或商业节点网络。

## 用户要完成的任务

| 用户任务 | 当前痛点 | MiaoTunnel 的回答 |
| --- | --- | --- |
| 从外网访问 NAS 上的 Web 应用 | 配置 FRP、DNS、证书、反代分散在多处 | 选择设备、端口和名称，一次发布 |
| 暂时接收 webhook 或展示开发版本 | SaaS 地址/额度受限，自建工具配置繁琐 | 自有域名下创建可撤销地址 |
| 给少量同事访问内部面板 | 直接暴露风险高，VPN 使用门槛高 | 默认密码保护，按服务开关与审计 |
| 排查“为什么打不开” | 用户无法判断是 DNS、证书还是内网端口 | 分层检查和可复制的脱敏诊断报告 |
| 设备丢失或 token 泄露后止损 | 共享密钥难以单独撤销 | 每设备身份、撤销与轮换 |

## 首版人物画像

### A. NAS 用户

- 有绿联、群晖、飞牛或 Unraid；
- 能运行 Docker，但不熟悉反向代理和证书；
- 已有一台低价 VPS 和一个域名；
- 需要访问相册、下载器、Home Assistant 等 Web 服务。

### B. 个人开发者

- 需要持续或临时发布本地 Web 服务；
- 在意自定义域名、TLS、日志最小化和可撤销性；
- 愿意用 CLI 安装 agent，但不想维护多份 TOML。

### C. 小团队管理员

- 管理少量设备与内部 Web 工具；
- 需要知道谁发布了什么、设备是否在线；
- 暂时不需要企业 SSO、多租户或 Kubernetes。

## v0.1 使用旅程

1. 在一台 Ubuntu VPS 上运行安装检查，确认 80/443/7000 TCP、时间和磁盘；
2. 输入根域名，例如 `tunnel.example.com`，按提示添加 `A/AAAA` 与 `*.tunnel.example.com`；
3. 创建首个管理员，生成 10 分钟有效、只用一次的 agent 注册令牌；
4. 在 NAS/Linux 启动注册命令，从交互输入粘贴令牌；agent 换取独立设备凭据并上线；
5. 创建服务：选择 agent、本地 URL、子域名和访问模式；
6. 系统先探测目标，再授权 FRP 代理、更新 Caddy、等待证书并做公网回环检查；
7. 页面显示地址和逐层状态；停用服务时立即移除公网路由。

## v0.1 功能边界

必须有：

- 单管理员初始化、登录、退出和会话管理；
- 一次性 agent 注册、在线状态、撤销；
- Linux amd64/arm64 agent 与 systemd；
- HTTP 目标和 WebSocket 透传；
- 平台子域名与自动 HTTPS；
- 默认 Basic Auth，可明确改成公开；
- 服务创建、启停、删除；
- DNS/证书/网关/隧道/agent/目标六层诊断；
- 脱敏审计事件、备份和恢复说明；
- 一台 VPS 的 Docker Compose 部署。

明确不做：

- 裸 TCP/UDP、P2P、整网访问；
- 自定义访客客户端；
- 多管理员、组织、RBAC、SSO；
- 多网关、高可用、Kubernetes；
- 计费、套餐、托管节点；
- 静默自动更新；
- 正向代理、通用出口、匿名隧道。

## 产品原则

1. **资源优先，不暴露隧道术语**：界面说“设备、服务、地址、访问策略”，高级页才展示 FRP。
2. **先验证再发布**：目标不可达、DNS 未生效或域名不归当前网关时，不触发证书签发。
3. **默认受保护**：新服务默认 Basic Auth；切换为公开必须确认用途和风险。
4. **错误必须可定位**：不显示笼统的“连接失败”，必须给出失败层、时间与下一步。
5. **可退出**：可导出服务清单和配置；停止项目后仍可回到原生 FRP/Caddy。

## 竞争位置

| 维度 | MiaoTunnel | FRP | Wiredoor/Pangolin | ngrok/cpolar 等 |
| --- | --- | --- | --- | --- |
| 自托管 | 是 | 是 | 是 | 通常否 |
| 首次使用 | 向导化 | 配置文件 | 完整控制台但部署较重 | 最简单 |
| 目标用户 | NAS/家庭/小团队 | 技术用户 | 团队/企业安全平台 | 开发者与付费用户 |
| 数据面 | 复用 FRP | 自身 | WireGuard/自有体系 | 闭源托管 |
| 默认安全 | 设备身份 + 服务保护 | 需自行组合 | 完整策略 | 平台策略 |
| 差异点 | 中文 NAS 模板与分层诊断 | 协议能力 | 完整访问平台 | 节点与全球网络 |

## 不做的承诺

- 不承诺比商业节点更快；
- 不承诺绕过运营商或地区网络限制；
- 不把 GitHub Star 当作安全审计；
- 不在没有基准测试前宣传吞吐、并发或延迟数字；
- 不建议把无自身认证的 NAS 管理页面直接设为公开。
